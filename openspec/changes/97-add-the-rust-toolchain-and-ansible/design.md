# Design

## Decisions

- **Install the Rust toolchain as the `rust` tool of `mise.toml`, pinned at one stable release and locked with `mise lock` for `linux-x64` and `linux-arm64`.**: `mise.toml:1:The tools that Debian sid does not have` shows that the file holds the tools that need a pinned version, and `Dockerfile:33:mise install --locked` shows that the build installs each tool from the lock file.
- **Copy the whole folder of the cargo command to `/usr/local/lib/devtools/rust` and link its five commands from the last stage.**: `Dockerfile:38:install -m 0755 "$(mise which "$command")" "/out/bin/$command"` copies one file per command, and `rustc` finds `lib/rustlib` beside its binary, so a copied `rustc` alone holds no standard library; `Dockerfile:150:COPY --from=python-tools /usr/local/lib/devtools/ /usr/local/lib/devtools/` and `Dockerfile:153:ln -s ../lib/devtools/copier/bin/copier` show the pattern of a copied tool folder with linked commands.
- **Locate the toolchain folder with `mise which cargo` and copy the two levels above that command, so the plan depends on no layout of `mise where rust`.**: The stage already resolves each command path with `mise which` at `Dockerfile:38:install -m 0755 "$(mise which "$command")" "/out/bin/$command"`, and the run checked no output of `mise where rust`.
- **Teach `test/manifests.sh` that the `rust` key provides five commands, print one command name per line from each `case` arm, and add the five names of the `rust/bin` targets of the `ln -s` list to the copied set.**: `test/manifests.sh:22:echo "$command"` prints one line per tool key, so a key with five commands would arrive as one line and the check would report the five Rust commands missing; `test/manifests.sh:28:s/.*for command in//` cuts the joined `Dockerfile` at the last loop, so the Rust names must come from the link list and not from a second loop.
- **Install `ansible-lint` as the fourth tool of the `python-tools` stage, from the hashed requirement file `python/ansible-lint.txt`.**: `Dockerfile:103:for tool in copier pre-commit semgrep; do` builds one virtual environment per tool with `Dockerfile:105:uv pip sync --require-hashes`, and `Dockerfile:153:ln -s ../lib/devtools/copier/bin/copier` links each command from its environment.
- **Add `--lockfile requirements.txt:python/ansible-lint.txt` to the `osv-scanner scan source` step of the Image workflow.**: The step names each Python lock file and is the gate of the image: `.github/workflows/image.yml:184:--lockfile requirements.txt:python/copier.txt` and `.github/workflows/image.yml:176:The gate of the image`.
- **Add the Rust version checks to the mise.lock block of `test/tools.sh` in alphabetical order and `ansible-lint --version` before `copier`.**: The script groups each tool by its installer: `test/tools.sh:61:The tools of mise.lock` and `test/tools.sh:2:Runs each tool of the image once and prints its version.`.
- **Change the message of `test/manifests.sh` to name the commands of the copy loop and of the links, so that the printed number matches the set that the check reads.**: `test/manifests.sh:42:tools of mise.toml.` prints one number for a set that now holds a tool with five commands.
- **Leave the image release to a person after the merge and plan no code for it.**: The workflow publishes only a tag (`.github/workflows/image.yml:27:The release that the run publishes`), and the `RUNNER_TOOLS` rows belong to the other repository.
- **Carry no spec delta: the change is the image build, its shell tests, its workflow and its documents, and the repository holds no `src/` package and no living spec whose requirement could describe this behavior.**: The run's `list_files` of the top of the commit returned no `src/` folder and no `tests/` folder, and the run's `list_files` of `openspec` returned only `openspec/config.yaml`, so no behavior group can change a `.py` file under `src/`; `test/manifests.sh:2:Checks that the copy loop of the Dockerfile and the tools of mise.toml name the same commands.` and `test/tools.sh:2:Runs each tool of the image once and prints its version.` are the proofs that this repository uses.

## Rejected alternatives

- **Install the Rust toolchain from the apt packages rustc, cargo, clippy and rustfmt.**: `Dockerfile:42:Each one floats with sid` shows that an apt package changes with the distribution, while `mise.lock:3:lockfile_version = 4` pins each mise tool for both platforms.
- **Install the toolchain with the rustup shell script in the `Dockerfile`.**: The image installs each binary tool from the lock file (`Dockerfile:33:mise install --locked`), and `test/manifests.sh:11:tomllib.load(open(sys.argv[1], "rb"))["tools"]` reads only the keys of `mise.toml`, so a second installer would add a tool that the check does not see.
- **Install `ansible-lint` with `uv tool install`, as the proposed design of the issue says.**: `Dockerfile:103:for tool in copier pre-commit semgrep; do` and `Dockerfile:105:uv pip sync --require-hashes` show one virtual environment per Python tool from a hashed requirement file, and `README.md:93:Each Python tool has a virtual environment of its own` states the layout, so the image holds no uv tool environment.
- **Install `ansible-lint` with pip into the system Python.**: `Dockerfile:105:uv pip sync --require-hashes` shows that each Python tool comes from a hashed requirement file of `python/`, and pip would add a second install path with no hash.
- **Install `ansible-lint` with the pipx backend of mise.**: `Dockerfile:100:--mount=type=bind,source=python,target=/tmp/python` shows that the Python tools come from the `python/` folder, and `README.md:84:pip-compile` names the one manager that updates them.
- **Copy only the five Rust commands to `/out/bin` with the other mise tools.**: `Dockerfile:38:install -m 0755 "$(mise which "$command")" "/out/bin/$command"` copies one file per command, and `rustc` finds `lib/rustlib` beside its binary, so a copied `rustc` would hold no standard library.
- **Add a second `for command in` loop to the `Dockerfile` for the Rust commands.**: `test/manifests.sh:28:s/.*for command in//` cuts the joined text at the last loop, so the check would see only the second loop's commands and report the 27 existing commands as missing.
- **Add one new block for all the new commands to `test/tools.sh`.**: `test/tools.sh:61:The tools of mise.lock` and `test/tools.sh:2:Runs each tool of the image once and prints its version.` show that the script groups each tool by its installer, and a mixed block hides which installer provides each tool.
- **Add no version check for the new commands.**: `test/tools.sh:2:Runs each tool of the image once and prints its version.` shows that the image test proves each tool by its version, and the issue requires a version check for each new tool.
- **Add a Python test that reads the `Dockerfile` and `test/tools.sh` and asserts the new commands.**: The run's `list_files` of the top of the commit showed no `src/` folder and no `tests/` folder, so a new test module has no package to mirror, and `test/manifests.sh:2:Checks that the copy loop of the Dockerfile and the tools of mise.toml name the same commands.` shows that the repository proves the image with a shell check and the live image build.
- **Make the Trivy image scan the gate that proves the new tools safe, as the proposed design of the issue says.**: `.github/workflows/image.yml:206:The scan is report-only` and `.github/workflows/image.yml:210:The gate stays on the lock files` show that only the osv-scanner step fails the job on a finding.
- **Add a capability with the requirements of the refine block.**: A behavior group MUST change a `.py` file under `src/`, and the run's `list_files` of the top of the commit showed no `src/` folder and no `tests/` folder, so every added scenario would stand with no behavior task; `test/manifests.sh:2:Checks that the copy loop of the Dockerfile and the tools of mise.toml name the same commands.` and `test/tools.sh:2:Runs each tool of the image once and prints its version.` are the proofs that this repository uses.
