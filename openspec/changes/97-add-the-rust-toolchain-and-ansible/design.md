# Design

## Decisions

- **Install `ansible-lint` as the first tool of the loop of the `python-tools` stage, from the hashed requirement file `python/ansible-lint.txt`.**: `Dockerfile:103:for tool in copier pre-commit semgrep; do` builds one virtual environment per tool with `Dockerfile:105:uv pip sync --require-hashes`, and `README.md:101` gives the steps to add a Python tool. The loop names the tools in alphabetical order, so `ansible-lint` comes before `copier`. The lock of ansible-lint 26.11.1 has a wheel of each package for each platform.
- **Link `ansible-lint` as the first line of the `ln -s` list of the last stage.**: `Dockerfile:153:ln -s ../lib/devtools/copier/bin/copier` links each command from its environment, and the list starts with the Python tools.
- **Accept the warning "PATH altered to include /usr/local/lib/devtools/ansible-lint/bin" of ansible-lint.**: ansible-lint prints it and exits 0 when its command is a link into a virtual environment that holds `ansible`. It then runs the `ansible` commands of its own environment, which match the `ansible-core` that it imports. Its version check sends no request, because the INSTALLER of the distribution is `uv`.
- **Add `--lockfile requirements.txt:python/ansible-lint.txt` to the `osv-scanner scan source` step of the Image workflow, and handle a finding by the rule of `python/osv-scanner.toml`.**: The step names each Python lock file and is the gate of the image (`.github/workflows/image.yml:176`). A finding with a released fix gets a higher pin. A finding that no release fixes gets one narrow ignore with a reason, a tracking issue and an end date 3 days ahead, as the header of `python/osv-scanner.toml` says.
- **Keep a failure of the expired semgrep ignores out of this item.**: The ignores of `python/osv-scanner.toml` for the lock of semgrep end at `effectiveUntil = 2026-11-30T00:00:00Z`. From that date, the `osv-scanner` step fails each Image run until a renewal of the ignores or the fix of #2 merges. That finding is in `python/semgrep.txt`, so a scan of `python/ansible-lint.txt` alone shows whether the new lock is clean.
- **Add `run ansible-lint --version` before `run copier --version` in `test/tools.sh`.**: The script groups each tool by its installer, and the Python tools `copier`, `pre-commit` and `semgrep` follow each other in alphabetical order (`test/tools.sh:94`). The script runs in the image with no network (`test/tools.Dockerfile:11`).
- **Tell the reader of `README.md` to add the lock file of a new Python tool to the `osv-scanner` step, and add the sid version of ansible-lint to the apt rule.**: `README.md:101` lists the steps to add a Python tool and does not name the `osv-scanner` step, which this change edits. `README.md:74` records the sid versions that sent a tool to a different source.
- **Plan no code for the release.**: release-please opens the release pull request, the release workflow turns on auto-merge, and the tag starts `image.yml`, which publishes the image (`README.md:180` to `README.md:183`). The `RUNNER_TOOLS` row belongs to the other repository.
- **Carry no spec delta: the change is the image build, its shell test, its workflow and its documents, and the repository holds no `src/` package and no living spec whose requirement could describe this behavior.**: `test/tools.sh:2:Runs each tool of the image once and prints its version.` is the proof that this repository uses.

## Rejected alternatives

- **Add the Rust toolchain to the image (`cargo`, `rustc`, `rustdoc`, `rustfmt`, `cargo clippy`, `cargo fmt`, and `gcc` with `libc6-dev` as the linker).**: The owner decided on 2026-11-27 that the image gets no Rust toolchain (update line of #97). The size evidence: the toolchain folder with the `minimal` profile, `clippy` and `rustfmt` was 652,936,685 bytes, `gcc` and `libc6-dev` added 245 MB, and ansible-lint adds 60 MB, about 0.96 GB in all. The devops-cli runner image, which builds FROM this image, is 6,296,100,499 bytes at release v0.224.2, so it becomes about 7.25 GB, over the bound of 7,000,000,000 bytes of devops-cli `ci.yml:687`.
- **Install `ansible-lint` from the apt package of sid.**: On 2026-11-27 sid had ansible-lint 26.4.0-2 while PyPI had 26.11.1, and the rule of `README.md:74` uses apt only where sid is current.
- **Install `ansible-lint` with `uv tool install`, as the proposed design of the issue says.**: `Dockerfile:103:for tool in copier pre-commit semgrep; do` and `Dockerfile:105:uv pip sync --require-hashes` show one virtual environment per Python tool from a hashed requirement file, and `README.md:93:Each Python tool has a virtual environment of its own` states the layout. A uv tool environment would install a second way.
- **Install `ansible-lint` with pip into the system Python.**: `Dockerfile:105:uv pip sync --require-hashes` shows that each Python tool comes from a hashed requirement file of `python/`, and pip would add a second install path with no hash.
- **Install `ansible-lint` with the pipx backend of mise.**: `Dockerfile:100:--mount=type=bind,source=python,target=/tmp/python` shows that the Python tools come from the `python/` folder, and `README.md:84` names `pip-compile` as the one manager that updates them.
- **Use the `ansible-core` of apt for ansible-lint and install ansible-lint with no `ansible-core` of its own.**: `uv pip sync --require-hashes` installs exactly the lock, and ansible-lint requires `ansible-core`, so the lock holds it; an environment that reads the packages of the system Python would break the one-environment-per-tool layout of `README.md:93`.
- **Make the Trivy image scan the gate that proves the new tool safe, as the proposed design of the issue says.**: `.github/workflows/image.yml:206:The scan is report-only` and `.github/workflows/image.yml:210:The gate stays on the lock files` show that only the osv-scanner step fails the job on a finding.
- **Add a Python test that reads the `Dockerfile` and `test/tools.sh` and asserts the new command.**: The repository holds no `src/` folder and no `tests/` folder, and `test/tools.sh:2:Runs each tool of the image once and prints its version.` shows that the repository proves the image with a shell check and the live image build.
- **Add a capability with the requirements of the refine block.**: The repository holds no `src/` folder, no `tests/` folder and no living spec, so every added scenario would stand with no behavior task; `test/tools.sh` is the proof that this repository uses.
